# 1C MCP

Проект для индексации структуры конфигурации 1С и экспортированного кода 1С, чтобы агент мог искать объекты, реквизиты, типы, модули и процедуры через MCP.

## Быстрый старт

Перед запуском должен быть установлен и запущен `Docker Desktop`.

Если ты открываешь проект на новом ПК и хочешь сразу подготовить базу знаний, используй:

```bash
docker compose run --rm --build index-structure && docker compose run --rm --build index-docs && docker compose run --rm -T mcp
```

Это:

- соберет индекс структуры 1С;
- соберет базу знаний из `docs/` и PDF-книг;
- запустит MCP-сервер, который увидит обе базы.

## Что здесь есть

- `data/СтруктураУТ11_5_22.xml` — основной экспорт структуры конфигурации 1С.
- `parser/indexer.py` — строит индекс структуры в SQLite.
- `code_indexer.py` — индексирует экспортированный код 1С и вытаскивает модули/процедуры.
- `docs_indexer.py` — индексирует справку 1С и другую документацию.
- `mcp/server.py` — MCP-сервер по `stdio`, который отдает инструменты агенту.
- `search/search.py` — локальный CLI для ручного поиска по индексу.
- `storage.py` — схема SQLite и все запросы.

## Как это работает

Проект хранит не саму конфигурацию 1С, а индекс по ней.

1. Берется XML со структурой конфигурации.
2. Из него строятся таблицы SQLite:
   - `docs`
   - `sections`
   - `metadata_objects`
   - `metadata_attributes`
   - `type_links`
   - `chunks`
   - `modules`
   - `procedures`
3. MCP-сервер читает эту базу и отдает инструменты агенту.
4. Если есть экспорт кода 1С, он индексируется отдельно и добавляет поиск по модулям и процедурам.
5. Если есть локальная справка 1С, она индексируется как отдельный слой `docs`.

## Что умеет MCP

Основные инструменты:

- `search_structure` — поиск объектов конфигурации.
- `get_structure_object` — полная карточка объекта.
- `search_attributes_tool` — поиск по реквизитам и табличным частям.
- `search_types_tool` — поиск по типам и ссылкам.
- `search_chunks_tool` — поиск по текстовым чанкам.
- `list_sections_tool` — список секций структуры.
- `search_procedure` — поиск процедур и функций.
- `search_code` — общий поиск по коду.
- `get_module_source` — получить текст модуля по пути.
- `search_docs` — поиск по справке и документации.

MCP-сервер работает через `stdio`. Это значит, что клиент не ходит на HTTP-адрес, а запускает процесс `python3 mcp/server.py` или `docker compose run ... mcp` и общается с ним JSON-RPC сообщениями.

## Запуск через Docker

Это основной и рекомендуемый способ работы. Python и зависимости на хосте не нужны.

### 1. Запуск MCP-сервера

```bash
docker compose run --rm -T mcp
```

При первом запуске контейнер сам построит индекс структуры, если `data/db/index.db` еще не существует.
После этого MCP-сервер ждет JSON-RPC запросы от клиента через `stdio`.

### 2. Ручная пересборка индекса структуры

```bash
docker compose run --rm index-structure
```

### 3. Индексация кода 1С

Сначала подготовь экспорт кода в папку на хосте, затем запусти:

```bash
CODE_EXPORT_DIR=/path/to/1c_export docker compose run --rm index-code
```

### 4. Индексация справки и документации

```bash
docker compose run --rm index-docs
```

По умолчанию индексер ищет локальную папку `./docs` рядом с репозиторием.
В этой папке можно хранить PDF-книги, HTML-справку, Markdown и TXT.
Если менялся `Dockerfile`, добавь `--build`, чтобы Docker пересобрал образ с `pypdf`.

## Подключение в VSCode

VSCode сам по себе MCP не использует. Нужен MCP-совместимый клиент или расширение.

Принцип подключения:

1. Клиент запускает сервер как subprocess.
2. Сервер отвечает на `initialize`.
3. Клиент вызывает `tools/list`.
4. Клиент дергает `tools/call` для нужного инструмента.

Пример запуска через Docker:

```json
{
  "mcpServers": {
    "1c": {
      "command": "docker",
      "args": ["compose", "-f", "/Users/admin/1c-mcp/docker-compose.yml", "run", "--rm", "-T", "mcp"]
    }
  }
}
```

Если клиент умеет запускать локальную команду без Docker, можно использовать:

```json
{
  "mcpServers": {
    "1c": {
      "command": "python3",
      "args": ["/Users/admin/1c-mcp/mcp/server.py"]
    }
  }
}
```

## Формат экспорта кода 1С

`code_indexer.py` ожидает папку с файлами экспорта 1С. Подходят:

- `.bsl`
- `.txt`
- `.xml`

Что делает индексатор:

- рекурсивно обходит папку;
- читает файлы в `utf-8`, `utf-8-sig`, затем `cp1251`;
- ищет объявления:
  - `Процедура`
  - `Функция`
  - `Procedure`
  - `Function`
- ищет окончания:
  - `КонецПроцедуры`
  - `КонецФункции`
  - `EndProcedure`
  - `EndFunction`

`docs_indexer.py` индексирует материалы из `docs/`. Подходят:

- `.md`
- `.txt`
- `.html`
- `.htm`
- `.pdf`

Что делает индексатор:

- рекурсивно обходит папку;
- для текста читает файлы в `utf-8`, `utf-8-sig`, затем `cp1251`;
- для PDF извлекает текст по страницам через `pypdf`;
- сохраняет материалы в таблицу `docs` и делает их доступными через `search_docs`.

Важно:

- индексатор не требует идеального формата, но ожидает обычный текстовый экспорт;
- если код не экспортирован, в базе будет только структура конфигурации;
- путь к папке с кодом передается явно в командной строке.

## Файлы и артефакты

В репозиторий не нужно коммитить:

- `data/db/index.db`
- `*.db-wal`
- `*.db-shm`
- `__pycache__`
- `venv`
- `.DS_Store`

Это уже исключено через `.gitignore`.

## Когда пересобирать индекс

Индекс нужно пересобирать, если:

- поменялся `data/СтруктураУТ11_5_22.xml`;
- ты получил новый экспорт кода 1С;
- хочешь обновить базу после изменения схемы хранения.

## Практический сценарий

Обычно рабочий цикл такой:

1. Открыть репозиторий на новом ПК.
2. Запустить `docker compose run --rm -T mcp`.
3. При первом старте контейнер сам соберет индекс структуры.
4. При необходимости отдельно проиндексировать код и документацию.
5. Подключить MCP в VSCode или другом MCP-клиенте.
6. Использовать поиск по структуре, коду и документации прямо из модели.

## Локальный режим

Локальные скрипты `parser/indexer.py`, `code_indexer.py`, `docs_indexer.py`, `search/search.py` остались как вспомогательные. Они не обязательны для обычной работы, если ты запускаешь проект через Docker.
